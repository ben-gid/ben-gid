PII Redaction API

Three fine-tuned DeBERTa-v3 models detecting 27 PII entity types across 55 BIO labels, served behind an API-key-authenticated FastAPI service on AWS ECS Fargate — custom domain, Cloudflare TLS, and a GitHub Actions pipeline that ships every push to main.

0.9557
Macro F1 · base
DeBERTa-v3 FastAPI Docker ECS Fargate GitHub Actions W&B
  • ·Custom WeightedTokenClassificationTrainer with class-balanced cross-entropy for severe O-token imbalance; two-phase training (frozen backbone → full fine-tune) in bf16.
  • ·Overlapping token chunking with sentence-aware boundary alignment and max-confidence overlap resolution, exposed through both a CLI and Pydantic-typed endpoints.
  • ·Rate-limited public demo (10/day per IP), 14 unit tests across auth, validation and edge cases, secrets via SSM Parameter Store.
  • ·All three checkpoints published to HuggingFace Hub with model cards covering per-entity F1, GPU latency, and distribution-shift behavior.

Flower Classification Service

A config-driven PyTorch Lightning sweep across 11 backbones, 71 runs tracked in MLflow — and the project where I found a data-leakage bug that had quietly inflated every one of those runs to ~1.0 accuracy.

  • ·Validation and test splits were being drawn from the training subset. Found it, re-evaluated both published models on genuinely held-out data, corrected the sweep's architecture rankings, and added test_splits_are_disjoint so it can't come back.
